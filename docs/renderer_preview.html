What is still missing for a 1:1 picture

Being precise about this, because the gap is one specific link in a chain.

The textures are decoded. Real building art comes out of the game's ASTC atlases correctly — that part works, and the sprites below are genuine pixels from sc/buildings_0.sctx. What is missing is knowing which sprite belongs to which building at which level.

The chain to close it, and how far along it is:

  1. Done. buildings.csv gives every building's per-level sprite name — a TH4 Cannon is basic_turret_lvl5.
  2. Done. Those names are in buildings.sc as 4-byte length-prefixed strings, and each is followed by a FlatBuffers table.
  3. Done. That table resolves to a two-field record — an id and a type.
  4. Missing. Following that id through movie-clip → shape → texture rectangle, to get the atlas coordinates. SC v6 is FlatBuffers with an unpublished schema, so each hop has to be mapped against real files.

Until step 4 lands, dropping real sprites onto the map means showing a max-level X-Bow where a level-2 Mortar belongs. That is worse than an honest diagram, so the map draws real footprints and levels instead.

Getting a layout into the game

A base link (TH17:HV:<32 chars>) decodes to 24 bytes — an identifier for a layout already stored on Supercell's servers, tied to an account and base slot. It cannot describe 150 buildings, so a layout designed offline cannot be minted into a working link. Only the in-game handler resolves them.
